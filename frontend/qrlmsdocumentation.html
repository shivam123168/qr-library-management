System Architecture

The system follows a three-tier architecture with clear separation of concerns:

Client Layer (Frontend)

Presentation Layer: HTML5, CSS3, and JavaScript provide the user interface. Three separate dashboards serve Librarians, Students, and Employees with role-specific features.

API Layer (Backend)

Business Logic: FastAPI handles all business logic with comprehensive endpoints for books, users, transactions, penalties, and QR generation. Includes JWT authentication, authorization, and role-based access control.

Data Layer (Database)

Persistent Storage: MySQL database hosted on Railway with comprehensive schema supporting books, users, transactions, penalties, and relationships.

Background Tasks & Scheduler

Automated Operations: APScheduler runs background tasks including automated penalty calculations and daily updates without manual intervention.

Database Schema

The database follows a normalized relational model with proper relationships and constraints:

Core Tables

Table Purpose Key Fields
students Student records PRN, name, branch, semester, email, phone
employees Employee records Emp_ID, name, department, post, email, phone
books Book inventory Accession#, title, copies, cost, location
issue_books Book transactions Issue_ID, book_id, user_id, issue_date, due_date
penalties Penalty records Penalty_ID, issue_id, amount, status, date
book_requests Book requests Request_ID, book_id, user_id, status
authors Author information Author_ID, name
publishers Publisher info Publisher_ID, name, place

Reference Tables

Table Fields Usage
branches branch_id, name Student branch classification
departments dept_id, name Employee department grouping
employee_posts post_id, name Employee position classification
penalty_amounts amount_id, rate, day_limit Configurable penalty rates
book_author_junction book_id, author_id Many-to-many book-author mapping

Database Relationships

  • ✓ Students 1:N Issue_Books (student issues multiple books)
  • ✓ Employees 1:N Issue_Books (employee issues multiple books)
  • ✓ Books 1:N Issue_Books (book issued multiple times)
  • ✓ Issue_Books 1:N Penalties (one transaction, one penalty)
  • ✓ Books N:M Authors (book has multiple authors)
  • ✓ Students 1:N Book_Requests (student requests multiple books)

Installation & Setup

Prerequisites Required: Python 3.8+, MySQL 8.0+, Git, and Node.js (optional)

Backend Setup

1

Clone Repository

Get the source code from GitHub

git clone https://github.com/shivam123168/qr-library-management.git cd qr-library-management/backend
2

Create Virtual Environment

Isolate Python dependencies

# Windows python -m venv venv venv\Scripts\activate # macOS/Linux python3 -m venv venv source venv/bin/activate
3

Install Dependencies

Install required Python packages

pip install -r requirements.txt
4

Configure Environment

Create .env file with configuration

# Database Configuration DATABASE_URL=mysql+pymysql://root:password@localhost:3306/qrlms # Security SECRET_KEY=your-super-secret-key-here-minimum-32-characters ALGORITHM=HS256 ACCESS_TOKEN_EXPIRE_MINUTES=30 # Application DEBUG=True PROJECT_NAME=QRLMS API VERSION=2.0.0
5

Create Database

Set up MySQL database

mysql -u root -p CREATE DATABASE qrlms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; EXIT;
6

Run Backend Server

Start the FastAPI application

python run.py # Server will be available at: # - API: http://localhost:8000 # - Swagger Docs: http://localhost:8000/docs # - ReDoc: http://localhost:8000/redoc

Frontend Setup

1

Navigate to Frontend

Change to frontend directory

cd ../frontend
2

Configure API Endpoint

Update API base URL in JavaScript files

// In JavaScript files: const apiBaseUrl = `http://localhost:8000`; // Local development // OR const apiBaseUrl = `https://your-production-url.com`; // Production
3

Run Development Server

Start local server using Python or Live Server

# Option A: Python built-in server python -m http.server 8080 # Option B: Use VS Code Live Server extension # Right-click index.html → Open with Live Server # Access at: http://localhost:8080
4

Deploy to Production

Deploy frontend to Vercel or static host

# Frontend is already optimized for production # Simply deploy the frontend folder to your hosting service # Examples: Vercel, Netlify, GitHub Pages
Security Reminder:
  • Change SECRET_KEY to a random, long string (minimum 32 characters)
  • Use strong database password in production
  • Never commit .env file to version control
  • Use environment variables from deployment platform in production
  • Enable HTTPS/SSL in production

All protected endpoints require JWT token in Authorization header:

Authorization: Bearer <your_jwt_token>

Response Format

{ "success": true, "data": { /* actual data */ }, "message": "Success message" } // Error Response: { "success": false, "error": "Error message", "status_code": 400 }

Frequently Asked Questions

What are the system requirements?

The system requires Python 3.8+, MySQL 8.0+, and modern web browsers. For development, Node.js is optional.

How do I reset my password?

Contact your librarian to reset your password. The system includes secure password change functionality for all users.

Can I export data to Excel?

Yes! The system supports exporting books, users, transactions, penalties, and other data to Excel format.

How are penalties calculated?

Penalties are calculated automatically based on the number of days overdue and configurable penalty rates. The system updates penalties daily.

Can students request unavailable books?

Yes! Students can request any book, and librarians can approve or reject requests. Approved books are automatically issued.

How do QR codes work?

QR codes uniquely identify books, students, and employees. Scanning a QR code quickly retrieves detailed information about the item.

Is there mobile support?

Yes! The system is fully responsive and works on mobile devices, tablets, and desktops.

How do I get support?

For issues and support, visit the GitHub repository issues section or contact the development team directly.
